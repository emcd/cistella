# Design: add-operation-logging

## Context

Cistella lifecycle paths (`conduct` install/start, `terminate`, `teardown`, `gc`) mutate shared host state (unit files, containers, attestations) under one HOME, one systemd manager, one container storage, and one creation lock. When a session breaks (e.g. the instrumented honest-red: container gone after `podman restart`, unit file gone by post-mortem), no durable record names the actor — concurrent global `gc` sweeps overlapped the window, but timing is not a mutation receipt. The surgery diagnostics collector captures per-poll evidence but performs no logging itself and must stay read-only.

Stakeholders: operator (merge gate), Advisor (correctness review), tier-1 (change review). Prior guidance (recorded): durable root under XDG_STATE_HOME, secure-path discipline reused, injected test metadata validated and never origin proof, logger failures must not influence decisions.

## Goals / Non-Goals

Goals:

- Every mutating lifecycle operation appends a durable, structured, bounded record: what ran, what it observed, what it decided, what resulted.
- The gc actor gets per-target records (plan, classification, action, result), not just a reaped list.
- A later failure (e.g. the surgery collector's post-mortem) can correlate against operation logs instead of inferring actors from timing.

Non-Goals:

- No change to gc scan/reap behavior, ownership, eligibility, or fail-closed semantics. No change to any product decision path.
- No log-based alerting, remote shipping, or query service. Logs are files; correlation is done by readers (tests, post-mortems, humans).
- No expansion of the read-only diagnostics collector into a logging subsystem; the collector stays a reader.

## Decisions

### 1. Durable root under XDG_STATE_HOME; runtime stages at most bounded coordination

`XDG_STATE_HOME/cistella/logs/<operation-id>/` (fallback `~/.local/state/cistella/logs/`), one directory per operation, length-prefixed frame records inside. Rationale: XDG_RUNTIME_DIR is ephemeral and cannot be the sole home of investigation evidence that must outlive the operation; Advisor and tier-1 converge on this. The runtime directory may hold bounded staging files (e.g. an open file handle target) but never the only copy; any runtime-only retention names its weaker lifetime and requires export before teardown.

Alternative considered: single shared log file. Rejected: concurrent writers from parallel tests would interleave records; per-operation directories give natural isolation and bounded cleanup units.

### 2. Reuse the secure-path discipline, not an existing tree

Creation reuses the repo's anchored-creation helpers (0700 directories, 0600 files, no symlink follow, uid-keyed ownership). The log root builds missing ancestors with the same discipline through a component-wise descriptor-anchored walk: every child is created with `mkdirat` and opened with `openat(O_NOFOLLOW|O_DIRECTORY)` against the retained verified parent descriptor, so intermediate symlinks refuse and no checked path is ever re-resolved; only created levels and the target receive the private-directory hardening. A symlink at any level refuses the open and nothing is created through a link. New logs do NOT go inside `cistella-state-<uid>` and do not mirror the lease layout: purpose-built tree, same discipline.

Logger-owned control and evidence files (the admission lock, eviction markers) are created and opened nofollow with regular-file verification: a planted symlink or FIFO fails the operation closed without touching anything outside the log tree.

### 3. Operation identity is generated; test metadata is injected and untrusted

Each operation mints its own id from a path-safe alphabet (lowercase alphanumerics, fixed length, sufficient entropy) and records a parent id where nested. Test-run id, exact SHA, test name, and parent operation id arrive only by explicit injection, are validated and length-bounded, and are recorded as claims, never as proof of origin. The envelope's argv label comes from a fixed operation vocabulary, never a rendered command line, so no untrusted path text lands in a label. Build provenance is limited to what exists at compile time today (`CARGO_PKG_VERSION`; no baked SHA, no build.rs) and is labeled as such. Labels and paths derived from validated ids only.

### 4. Record shape: envelope, per-target decisions, and only what was observed

Envelope per operation: operation id, parent id, actor verb plus a role from a fixed mapping, pid plus process start identity, argv label from the fixed operation vocabulary (unknown verbs map to a fixed label), start wall-clock timestamp. The terminal record carries the end wall-clock timestamp, the monotonic duration, and the outcome. Per-target entries for gc record the observed container-exists disposition, the unit properties actually read, explicit not-queried/unavailable markers for unread fields, and abort receipts when the scan fails before classification. Nested teardown calls carry the gc operation id as their parent. Per-target entries for gc: session id, attempt/reconciliation key, unit name + InvocationID, full container id, observed state (exists code, inspect disposition, unit props), decision with reason code, action and result/errno. The gc phases map directly onto source structure: phase-1 classification (`to_reap` / `live_sessions`), phase-2 teardown + `podman rm -f` per classified orphan, tmpdir and attestation phases after. Other operations (install/start, terminate, teardown) use the same envelope with operation-specific observed/decided fields. Start record opens the log; the terminal record closes it; body records carry sequence numbers.

A record carries exactly the observations the deciding code path already made, with explicit `not-queried`/`unavailable` markers for fields the path did not read. No additional backend queries are issued to fill log fields and the decision is never re-evaluated after the fact. Rationale: gc reads fields conditionally, so InvocationID, container id, and exists code are not always available; inventing reads to complete the log would change the backend load and timing of the observed path. Any extra observation beyond the decision's own reads would be a separately bounded optional probe — this design includes none. Records form a declared state machine (start first and only first, body records while open, at most one terminal record last, enforced on read); reads are byte-bounded independent of any metadata pre-check and refuse oversize files outright. Every control-file read opens non-blocking with symlink-following refused and reads only verified regular files. Reservation accounting never turns uncertainty into zero: unreadable, overlarge, or invalid entries are charged one full share, listing failures refuse the open, and enumeration is bounded. Records form a declared state machine (start first and only first, body records while open, at most one terminal record last, enforced on read); reads are byte-bounded independent of any metadata pre-check and refuse oversize files outright. Openings may name an explicit validated id; invalid ids are refused before any reservation. — this design includes none.

### 5. Logger failures are observability losses with a bounded, disclosed perturbation

A write failure, partial record, or concurrent-writer interleave is recorded (or noted as missing) and MUST NOT flip a reap decision, a safety outcome, failure propagation, or fail-closed behavior. Logging sits beside the decision, after it; gc's inspect-failure abort path is untouched by logging code. New input/output, pruning, and fsync change timing, blocking, and lock scope, so the promise is unchanged decision semantics with bounded disclosed perturbation — one append per decision point, fsync on close only, prune best-effort off the hot path — never zero runtime effect and never "negligible" as fact. Storage is length-prefixed frames (4-byte big-endian length, maximum frame payload 256 KiB, checks against the maximum and the remaining file before allocation) written by the single owning writer of each operation file (no multi-writer joins; concurrent operations use separate files), so a torn tail is definitively detectable and handled by the stated reader contract: discard the torn frame and every byte after it, preserve the valid prefix, record the discard in the derived result, and read a missing terminal as UNKNOWN. On detecting a partial write the writer stops that stream and marks the loss (best-effort UNKNOWN terminal on an intact stream, or separate loss evidence - never a new frame behind the torn one). The finalization window is held by a marker file (`Operation::begin_finalization` creates it, `Operation::end_finalization` renames it to finalized evidence; `close` drives the pair around the terminal write plus fsync), and the pruner skips marker-bearing operations with live owners; a completed operation without a marker is policy-eligible including in its own maintenance pass. `close` holds the admission lock across the whole finalization window so a concurrent prune unlink cannot land between the terminal write and the fsync; on contention the terminal write is skipped and the log stays explicitly incomplete rather than finalizing unprotected. The pruner likewise holds the lock across its unlink-time recheck and unlink, and defers victims when contended rather than forcing them. Unit properties are recorded through a three-state observed type (never-queried, queried-but-missing, observed value) so a failed query never reads as an observed default. The per-candidate mapping from raw observations (inspect status, exists result, error text, property map) to decisions and observed values is the pure `classify_candidate` function — the gc's only classification path, recording exactly what it returns — so unit tests drive the production producer with missing and empty property maps rather than a hand-built fixture. Selection and eviction are separate steps so a test can plant a marker between them and prove the unlink-time recheck skips it. The deterministic logger-fault pin exercises the actual gc decision/action path with injection at the real writer seam, not permission heuristics or a duplicated logger-only model.

### 6. Bounded total retention with admission control and a reserved failure budget

The hard logical budget is 3 GiB of operation bytes for the whole tree. Admission control enforces it: each open writes an owner-attributed reservation file before creating its operation directory, reserving one metadata share plus one full per-operation cap; reservations release on close and on drop, and dead owners are reaped on the next open; an explicit-id open releases its reservation when construction fails after it. The reservation covers operation bytes, failure and incomplete operations, active operations, and eviction-accounting records, with bounded coordination under a nonblocking admission lock (contention skips logging). Empty and abandoned directories count as metadata against the budget. The physical filesystem may transiently overshoot the logical budget by reservation metadata plus at most one in-flight frame per active writer, and those bounds are the only permitted excess. When the budget cannot be secured, the open is refused while the business operation proceeds unchanged; the loss is observability only.

Inside the tree, a reserved failure budget of 1 GiB is protected: success-outcome operations are pruned by count (most recent 2000) and by age (7 days, whichever is smaller) without consuming the reserve; failure-outcome and incomplete operations are exempt from count pruning, bounded by the 1 GiB reserve and the 7-day age bound. Exhaustion evicts oldest-first with one accounting record per eviction run. Incomplete operations (no terminal record) count against the failure reserve and age out by 7 days; active ownership is pid plus process start identity (no mtime or PID-reuse proof), and inactive-incomplete operations are eligible victims so abandoned empty directories are never immortal. A present finalizing marker with a live owner protects the operation through finalization; completed operations without a marker are policy-eligible, including in their own maintenance pass. Selection and eviction are separate steps so tests can plant a marker between them and prove the unlink-time recheck skips it. The pruner skips actively-written operations, bounds its scan work per run, acquires no lifecycle locks, and never waits unboundedly. No secrets, no full ambient environment in records. Post-close eviction is maintenance, not enforcement — the admission protocol is what makes the cap real.

### 7. Raw logs separate from excerpts

The log file is a sequence of length-prefixed frames and is never rewritten. Any human or test excerpt (e.g. attached to a failure report) is a derived rendering with its own truncation markers; the raw path is always cited alongside. The reader contract (discard-and-record torn tails, UNKNOWN for missing terminal records) is normative in the spec; framing only makes the torn case definitively detectable.

## Risks / Trade-offs

- [Observer perturbation] Writing during gc perturbs the timed path it observes → Mitigation: single append per decision point from the decision's own reads (no extra backend queries), fsync on close only, prune best-effort off the hot path; the perturbation is bounded and disclosed, never zero by claim.
- [Disk exhaustion] Logs on a busy seat, including failure accumulation → Mitigation: total-tree 3 GiB hard budget enforced by admission reservations (nonblocking lock; contention skips logging), protected 1 GiB failure reserve, per-op 1 MiB cap, eviction with accounting records, best-effort prune-on-close plus age bound; overshoot bounded to reservation metadata plus one in-flight frame per writer.
- [Concurrent writers] Parallel tests append under one HOME → Mitigation: per-operation directories with a single owning writer each (no shared file, no multi-writer joins), anchored creation, prune skips active operations.
- [Attribution overreach] A log entry is evidence, not proof (missing logs, crash gaps, bounded lifetime, unenumerated actors) → Mitigation: requirements state correlation limits; incomplete operations read UNKNOWN; no claim stronger than the record.

## Migration Plan

Additive only: new directories and files, no migration, no rollback beyond deleting the tree. Readers (tests, post-mortems) adopt opportunistically; absence of logs never fails a pre-existing assertion. The motivating CI use case additionally depends on a workflow change outside this proposal: uploading the operation-log tree as a runner artifact (alongside the existing suite/audit logs). Until that workflow change lands, durable attribution holds for the local seat only.
