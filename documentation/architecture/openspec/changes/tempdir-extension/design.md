# Design: tempdir extension

## Context

0.3 proved external guests resolve, verify, and host (registry + same-FD anchor + role binding), but every extension in the tree is either shipped (Landlock) or a test peer. Session `/tmp` today is the image's own, with the driver-appended `/tmp/scratch` outlet as the sole writable path under confinement. Agentmux burns rounds on that limitation. Stakeholders: seat operators (registry authors, profile authors), Agentmux (first consumer), reviewers (tier-1 + tier-2 — the RW admission reverses a tier-2 hardening, carried here by explicit operator direction).

## Goals / Non-Goals

Goals: a third-party extension providing per-session RW `/tmp`, resolved through the seat registry; prepare carrying session identity; declared-RW honored end to end (merge, Landlock, launch); contributed host state reaped at teardown. Non-goals: removing `/tmp/scratch` (later migration); the full handler-registry redesign (`cistella:todos/44` — this change adds only the reap hook point the teardown needs); multi-extension composition (still v1 single); Windows/macOS seat paths (Linux-only, as today).

## Decisions

- **Session id rides the prepare request as an opaque string.** The driver already mints it (container names, scratch paths); extensions receive it but never parse it (opaque session identifier, as the operator directed). Rejected: deterministic path conventions (fragile cross-component coupling), ambient env passing (sloppy authority), profile supplements (static per-profile values cannot carry per-session identity). Additive field, major unchanged; old guests ignore unknown request fields.
- **RW contributions merge, then enforce centrally.** `refuse_extension_rw_mounts` is deleted, not narrowed: operator direction is honor-whatever-is-contributed, no exceptions. Safety stays in the central validators that already own each set (mount topology validation, collision refusal, lattice evaluation, hook-executable binding) — the same gates that vet RO contributions today. Rejected: scoped admission (e.g. RW-only-under-/tmp) — a second hardcoded policy would re-create the exact fight this change settles; declarations are authoritative intent.
- **The extension mints uniquely-named slices and declares them for cleanup; the driver reaps declarations only.** The guest creates `<temproot>/cistella-tmp-<session>-<rand>` under the seat temp root (`$TMPDIR` when set and absolute, else `/tmp` — standard temp conventions, so confined seats and capacity redirects work; gc enumerates the same computed root) with framework-minted session id for attribution, randomness for uniqueness, O_EXCL create-fail retry, 0700 and contributes `{host, /tmp, rw}` plus a `cleanup` list naming the minted directory. Teardown removes ONLY declared cleanup paths — never every contributed mount (a contributed RO project directory must survive its session). Reap separates root admission from traversal: at merge/admission the framework records the declared root identity (dev+ino of the root plus its parent association — the only observation point where the object is known good), and at reap time the root must still name that identity (a regular-directory replacement has a different dev+ino and refuses exactly like a symlink swap), be a non-symlink, and be seat-or-root owned. Ownership plus kind alone cannot distinguish a replacement directory from the minted slice; the recorded identity can. Traversal then runs via anchored directory FDs, ordinary files unlink without following, and nested symlinks unlink as entries (never traversed — harness-built symlinks are normal, and refusing the whole reap over one link would litter forever). Runs after converged teardown; removal failure is litter, never residue. Rejected: reaping every contributed mount (deletion authority over legitimate data), refuse-on-any-symlink (permanent litter from ordinary harness behavior), follow-symlinks (traversal escape), extension-side reaping (the guest is gone at teardown).
- **Prepare failure and lost responses reconcile through gc.** If the guest mints then fails before responding (or the response is lost/invalid), no merged plan exists to reap from — and "no live unit" does not prove orphanhood, because minting happens during prepare before any unit exists. The driver therefore holds a durable prepare lease (`<runtime>/cistella/prepare-<session>`, O_EXCL created, atomically updated) across each hosted prepare, recording driver pid, a pending marker before each spawn (cleared by the matching record — a crash between spawn and record leaves gc skipping, never assuming), plus one guest pid and process-group line per hosted guest. A dead driver pid does NOT prove the guest quiescent — the prepare guest runs in a separate process group, so abrupt driver death can leave it alive and still minting. `gc` therefore reaps only when the driver is dead AND all recorded guest process groups are dead AND no unit lives; a live driver, a live guest group, an unreadable/malformed lease, or a lease with no guest identity yet all mean skip (fail-closed leak, never unsafe deletion). Nothing is ever signaled — observation is signal-0 only (EPERM counts alive), so a reused PID can never be killed through the lease. A dead-driver/all-recorded-groups-dead lease is stale (removed, orphan rules after); the spawn-to-identity-update microsecond window stays conservative (no guest identity plus dead driver means skip). Rejected: parent-death-signal supervision of prepare guests (global spawn-path behavior change with its own race mitigation and availability risk — observation-only reconciliation needs no guest cooperation and cannot kill strangers). Declared-path reap (explicit per-session authority, visible in the plan) and pattern-enumerated gc (session-attributable prefix only, never arbitrary names) stay separate powers: arbitrary filesystem names cannot become cleanup authority behind the operator back.
- **Old request decoders tolerate the session id (pinned, not assumed).** The additive field keeps the major; conformance pins an actual old guest binary completing prepare against a session-id-carrying request. The opaque id is never parsed by guests; path construction uses the fixed prefix plus validated session charset plus randomness with exclusive-create — no unsanitized concatenation.
- **Landlock grants the admitted slice FULL, nothing else changes.** The compose rule already grants every declared RW target full rights wherever it sits; the `/tmp`-denied default stays for undeclared paths. The tempdir triple is the first RW triple targeting a system path, so it exercises the rule rather than adding one. `/tmp/scratch` nesting is preserved by depth-ordered mounting (`/tmp` before `/tmp/scratch`); the scratch triple keeps its existing subtree handling.
- **Pair composition with one central merge.** v1 conducts landlock plus at most one other extension (general N stays deferred): each answers prepare independently in declaration order, the raw plans concatenate, and the single central merge stays atomic under existing validators (collisions across plans refuse deterministically; hook order follows declaration order). This is the only way the tempdir proof (RW/FULL plus retained sibling denial) runs through production conduct — a hand-composed fixture the CLI cannot select proves nothing. Rejected: scoping v1 to unhooked tempdir (guts the Agentmux value — their seats are hooked), and general N now (ordering/conflict design deserves its own change).
- **Vendoring: fixture-grade reference, registry-resolved.** The reference extension builds beside the framework tests (example-grade binary, never an installed sibling), resolving by absolute-path registry entry in dogfood/dev — placement confers no discovery, and Default `cargo install` sets never include it. Real third parties vend their own. Revisit promotion to a packaged artifact on the second third-party guest.
- **Teardown hook point, not a handler registry.** The reap duty needs exactly one new lifecycle slot (post-converge host-state cleanup with the merged plan in scope). The general handler registry (`cistella:todos/44`) is designed separately; this slot must fit wherever it lands (flagged as an open question, as registration flagged the seat tier).

## Risks / Trade-offs

- [Risk] Malicious/buggy extension contributes RW `/` or sensitive targets → Mitigation: contributions were never trusted — topology validation, collision refusal, and Landlock scoping still vet every triple; profiles opt in per extension; registry is seat-operator-authored. The removed refusal was defense in depth, and the operator explicitly accepts its removal.
- [Risk] Slice leaks on teardown failure → Mitigation: best-effort removal plus attributable `gc` ownership (session id in the name; never under an active session).
- [Risk] Two sessions share a slice (name collision) → Mitigation: randomness per invocation plus O_EXCL-style create-fail retry in the guest; collision fails the prepare loudly, never shares.
- [Risk] Reap deletes legitimate data (contributed RO project dir) → Mitigation: declarations only — undeclared contributed mounts are never reaped, nofollow recursive removal refuses symlinks and non-directories.
- [Risk] Reap races a surviving harness → Mitigation: reap runs only after converged teardown (litter verdict requires termination/removal converged first).
- [Risk] `/tmp/scratch` outlet interplay (nested triple under the new `/tmp`) → Mitigation: depth-ordered mounts plus existing subtree handling; pinned by a nesting conformance test.
- [Risk] dev/ino identity aliases a replacement on recycling filesystems → Mitigation: none available short of birth-time (which tmpfs lacks entirely) — accepted with the accurate bound: a recycled-inode false match causes recursive deletion of a POPULATED replacement directory (remove_tree empties before rmdir), not merely an emptied dir. Contained by the trusted seat/root parent-writer exception (staging a same-path replacement requires parent-write powers already restricted to trusted actors) — never live data outside that trust. The identity check still refuses every detectable case. Proven on ext4 (freed inode recycled immediately); deliberately not forced via allocator tricks in tests (fragile the other way). Prior approval must not be cited as guaranteeing recycled-inode replacement detection: dev+ino is not lifetime-unique object identity after the original inode is freed.

## Migration Plan

Additive: new extension binary (absent unless installed), new registry entries (absent unless authored), new prepare field (ignored by old guests), deleted refusal only affects profiles declaring extensions that contribute RW (none exist today — Landlock contributes RO + hooks). Rollback is commit revert plus registry-entry removal; with no tempdir entries every profile behaves exactly as before. `/tmp/scratch` untouched.

## Open Questions

- Handler-registry fit (`cistella:todos/44`): the reap slot defined here must fit wherever that registry lands — flag at review if it conflicts.
- Promotion of the fixture-grade reference to a packaged artifact: revisit on the second third-party guest or when fleet needs an installable tempdir (not this change).
