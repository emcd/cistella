## Context

The v1 composition path (`prepare_pair` in `src/framework/prepare_select.rs`) already implements most of the N-law by accident: per-plan capability gating before concatenation, declaration-order concat, one atomic central merge (`merge_transacted_as`), per-name provenance, reverse-order shutdown with first-residue-dominates. The v1 limit is a single gate (`non_landlock > 1` refuses) plus a pair-shaped runner. Hooks today are landlock-shaped: `require_declared_hooks` plus a launch-plan-time singleton refusal, with `compose_hook_argv` assuming one hook set. Contributions (`PreparePlan`/`MergedPlan` in `src/framework/contract.rs`) conflate placement and rights inside mount triples.

Stakeholders: framework (merge owner), landlock + tmpdir guests (first re-proof subjects), SSH (first triple consumer, next change), RG + Advisor reviewers.

## Goals / Non-Goals

**Goals:**

- N-extension sessions with deterministic merge order and conflict semantics.
- A hook registry with three phases and explicit claimant rules.
- Placement/rights split so carveout derivation reads declared rights, not triple modes.
- Landlock+tmpdir re-proved under the merge pipeline in this change.

**Non-Goals:**

- The SSH extension itself (next change; triple pins land there).
- Live-guest finalize (needs its own threat model; finalize is observation-only here).
- Backcompat for the v1 pair rule or the old contribution shape (pre-1.0, break freely).

## Decisions

- **Generalize `prepare_pair` into `prepare_many`; delete the v1 gate.** The pair body is already the N-law — gating, concat order, atomic merge, provenance, shutdown discipline all stay byte-for-byte. Only the arity refusal goes. (Alternative: keep a separate pair fast-path — rejected, two paths means two merge semantics to pin.)
- **Concrete phase sequence (HIGH-4):** resolve → lease → host in declaration order (pending markers) → per-guest prepare+gate against its own negotiated set → collect → admission → concat → atomic central merge → lattice → compile → supervisor plan → stage/launch → attestation gate → converged teardown → finalize observations. The prior draft's "all dispatch after merge" was wrong for prepare (it supplies the merge inputs); this sequence is authoritative.
- **`Rights` lattice with join semantics and one effective-permission source of truth (HIGH-1, round-2 refined).** `Rights` is `Read`/`Write`/`Full` (wire `read`/`write`/`full`); `Full` is exactly `Read ∪ Write`. Join key is the canonical container target: exact duplicates (same target, provenance, and rights) refuse typed as ambiguous guest output, overlapping declarations join, cross-claimant declarations join with ALL provenances recorded. (Alternative: refuse any multi-claimant same-target rights — rejected, the flagship landlock+tmpdir pair both declare over `/tmp`; join is deterministic and matches the existing "declared RW grafts compose into FULL carveouts" doctrine.) Mask meanings are exact, not inferred from names: `Read` renders to the ancestor mask (EXECUTE + READ_FILE + READ_DIR — execute included, no write bits, no TRUNCATE, no dir mutation); `Full` renders to the full matrix (bits 0–14 including TRUNCATE). `Write` normalizes to effective `Full` at map construction, BEFORE every consumer — grant classification, alias accounting, retention, descendant checks, rendering, revision, supervisor — so no guard ever classifies actual FULL backend rights under a non-FULL label (the alias hole stays closed: a `Write` placement's host source joins FULL-source accounting exactly like a `Full` one, forcing retention-or-refusal on every RO route to its dentries). Permission labels are minimum grants plus audit metadata: they join (least upper bound of minima) into the normalized grant, and the original `(claimant, label)` pairs are preserved in the map entry for audit and pins. ORIGINAL BINDING INTENT is separate enforcement-bearing state in the same entry — the most restrictive declared binding per target (RO if ANY claimant declared read-only, including driver ro and file bindings; else RW). Retention and revision consume that state PLUS the normalized grants: a read-only intent at a retention position (target at/under a FULL route, source at/under a FULL source, per normalized grants) stays VFS read-only; a read-only intent outside FULL revises to read-write with Landlock carrying the original intent; files render verbatim. Only effective `Full` composes full-rights carveouts; `Read` entries compose readability rules exactly as today (uncovered targets get them, covered targets ride their route). The rationale is fleet backend POLICY, not mask incapability (correction of the prior draft: the syscall path takes independent bits — WRITE_FILE is distinct from READ_FILE): this session's baseline already grants read-execute broadly (ancestor R+X routes, `/` allow-ro), so a write-capable rule withholding read would be theater — the grantee reads via baseline routes regardless. The conservative Full approximation is explicit, and all guards see it.
- **Declared intent versus rendered binding are separate layers; the safe RO→RW revision is preserved (round-2 HIGH).** The prior draft's "driver modes untouched / RO always stays VFS RO" was wrong: `revise_ro_for_confinement` deliberately renders a declared-RO directory outside FULL grants as Podman RW so submounts materialize, with the Landlock policy derived from the ORIGINAL declared intent enforcing the RO in-container — and retains Podman RO exactly where the Landlock union cannot subtract (target at/under a FULL route, source at/under a FULL source), plus files always verbatim. That logic is preserved byte-for-behavior, but its inputs move from triple modes to the `EffectivePermissions` map: "declared RO" for an extension contribution means effective `Read` without `Write`/`Full`; driver triples feed the map with driver provenance (ro→`Read`, rw→`Full`). Profiles translate 1:1 at the declaration layer; rendered behavior is preserved because the revision is preserved — not because modes are untouched. The VFS floor is computed from normalized grants AND retained binding intent — never from grants alone: join widens grants (a `Read` meeting a `Write` on the same target yields effective `Full` for Landlock, both claimants recorded), but the read-only binding intent survives join as enforcement state. Driver RO plus extension `Write` on the same target under FULL therefore stays VFS read-only (retention reads the intent) while Landlock grants `Full` — writes fail at the filesystem layer, exactly the retained-RO doctrine. What join cannot do is erase binding intent: minimum grants join, binding intent persists. Intent authority is explicit: contributed placements derive bindings from intent (the rendering above); driver bindings render from declared modes, never from extension intent — an extension Read on a driver-RW target records intent for audit without vetoing the driver binding, while a driver-RO intent plus any Full grant retains read-only through the existing retention. Validation renders contributed placements through the same intent-aware view (never a rights-only synthesis that would refuse safe RO+RO outcomes). The safe RO→RW revision runs ONLY when a hook is applied; plain sessions render declared modes verbatim (existing behavior — without Landlock there is nothing to carry the revised intent). A contributed placement with no matching permission refuses typed, as does a permission matching no addressable target — there is no silent default, so grant-only or omitted rights can never widen anything. Extension-contributed Podman binding modes render from effective rights through the preserved revision (`Read`→ro-then-revise, `Write`/`Full`→rw). One `EffectivePermissions` map, computed once post-merge, serves every consumer — grant computation, `full_grant_sources`, graft/baseline alias guards, RO-retention, contradictory-descendant checks, final topology rendering, and the revision itself — so argv composition and policy cannot disagree the way independent readers of triple modes could.
- **Permission match scope (round-2 HIGH).** A permission target is addressable iff it matches (a) a placement contributed by ANY guest in the same session — cross-guest matching is the landlock-grants-FULL-over-tmpdir's-slice mechanism, not laundering, since each side passed its own per-plan gate; (b) a driver/profile/CLI/worktree target; or (c) a known image-private baseline target (today: guest `/tmp` and `/dev` — the fixed FULL baselines, which need no placement). A permission matching none of these refuses typed as an unknown grant target; the namespace never widens silently. In particular the landlock-only `/tmp` permission (no tmpdir placement) matches baseline (c), which is the promised image-`/tmp` preservation.
- **`inject-supervisor` inputs gain the map (round-2 HIGH).** Roots plus modeless merged placements plus the index cannot derive grants without re-reading modes — so the supervisor takes confinement roots + merged placements + the `EffectivePermissions` map + declaration index. Lattice evaluation already ran at merge before supervisor dispatch; the supervisor composes argv from decided state, not policy. (Alternative: pass the lattice — rejected, it re-opens decided questions inside argv composition.)
- **One authoritative discriminator: the protocol epoch moves 1→2 (round-5 HIGH).** The break is wire-global — hello precedes everything and is shared by isolator and extension guests — so a second per-shape capability (`prepare-shape`) would add a redundant mechanism with join semantics to specify; it is dropped. `PROTOCOL_MAJOR` becomes 2 for host and ALL guest-role binaries (shipped landlock/tmpdir/podman guests plus registered-guest expectations); no legacy-1 constant may remain in any guest-role type (grep-pinned). 'Before body parsing' means bounded envelope/framing parses to read the version while incompatible operation payloads never decode — mismatch proves no prepare dispatch, no state minting, no compile. Coverage is hello-layer unit tests in both directions with deliberately incompatible payloads (mode-bearing, unknown-field prepare bodies): legacy-v1 hello vs epoch-2 host refuses naming the VERSION (asserted: version error, never shape/serde error); epoch-2 guest vs legacy-v1 host refuses before contributing. Dummy version numbers alone prove nothing — the pins use actual v1 vs 2 with incompatible bodies. Pre-1.0 states the sharp break plainly: no shim, no binary harness (operator directive 2026-10-14, tier-2-accepted substitution with the lost legacy-binary coverage stated on the record, not silently dropped).
- **Per-guest admission closes the union-set paths (HIGH-3).** `gate_capabilities` extends to the full transacted unit — plan plus credentials plus permissions — pre-concat, so GuestA's unadvertised credentials can no longer borrow GuestB's advertisement at the later union gate. Policy claims are scoped guest-locally: a guest's claims may target only names it contributed in the same transaction (partition runs per-guest pre-concat on own names); cross-guest targeting refuses typed rather than silently preserving the laundering. Provenance is host-assigned at hosting (the guest id) and carried on every contribution, claim, credential, and permission — wire self-reports stay ignored as today — kept as a multimap through validation so collision errors name ALL claimants with no last-writer attribution; a missing provenance entry is a typed internal refusal, never a guessed first/last guest.
- **Single hook set, single request, records-only finalize (HIGH-4).** Admission allows at most one nonempty guest-hook set containing at most one hook request: one guest returning two hooks refuses exactly like two guests returning one each (counting nonempty plans alone does not enforce today's compose singleton). Artifact/executable admission, the selected-but-empty refusal, and ABI/attestation gating stay central — landlock gets no merge privilege, but the central gates it today relies on remain. Finalize takes the restrictive option: it records already-admitted declarations and outcomes only, creates no actions and no new deletion authority. Follow-up cleanup declarations are out — they would need pre-admission through the existing cleanup identity gates, which is future work, not a finalize side-channel.
- **Landlock keeps no merge privilege.** Shipped-vs-registered stays resolution-only; merge treats every provenance uniformly. Duplicates keep refusing at profile resolution (existing behavior, unchanged).
- **N-runner proof executes ≥3 hosted guests (MEDIUM-5).** Fixture peers are legitimate for protocol/lifecycle unit behavior, but arity>2 must run landlock + tmpdir + a test peer through the real `prepare_many`: per-plan gating including the later guest, mid-host and mid-prepare failure with reverse shutdown of all hosted groups, residue dominance with pending-lease retention, and cleanup-on-collision. The real SSH triple receipt stays an explicit next-change obligation — this change proves the runner, not the third production guest.

## Risks / Trade-offs

- **Post-prepare, pre-isolation compile hook (amendment 2026-10-14).** AT MOST ONE claimant; frozen admitted snapshot in, typed rendered plan out. Snapshot contents: canonical placement IDs with source/target identities, normalized grants, original binding intent, provenance, backend capabilities, snapshot fingerprint. The compiler may change RENDERED modes for existing binding IDs and supply its backend policy/supervisor artifact; it may NOT edit admission intent, invent or change host sources/targets, touch env/credentials/cleanup, reorder ownership, or reopen decided lattice policy. Compiler output binds to snapshot AND enforcement consumer (no CompilerA rendering paired with SupervisorB policy). Unknown/missing/duplicate IDs, missing input bindings, stale fingerprint, and unsupported enforcement refuse before create. A legitimate isolator with no binding renderer declares placements unsupported/not-applicable — never silently drops requested placements. Bounded frame deadlines, lease tracking, and reverse shutdown cover a retained-guest compile phase (in-process module first; a future cross-process render op only if in-process ownership proves insufficient). No live finalize.
- **Validation boundary: generic checks only (amendment 2026-10-14).** The framework checks closed output grammar, input coverage and identity, snapshot binding, delegation/claimant limits, unchanged authority metadata, and no extra mutation domains. It MUST NOT recreate Landlock algorithms in a supposedly generic verifier — backend-specific grant/alias/retention validation moves with the code to its owner, and the effective policy result plus render decisions are consumed together. The compiler is trusted enforcement code like the isolator. Whether a backend can enforce a conditional RO floor after rendering RW is a backend capability/validation decision; generic floor enforcement covers abstract access/binding constraints only. Known-good denial/alias/materialization behavior stays pinned through the relocation, including plain-session no-revision.
- **Sugar decomposition into one canonical IR, early (amendment 2026-10-14, weaves todos/38).** Legacy mount mode ro decomposes to placement + `Read` grant + original read-only binding intent; rw to placement + `Full` grant + writable intent. Explicit `[[permissions]]` entries land in the same canonical guest-visible namespace in a source-labelled map. `Write` normalizes to effective `Full` consistently; original binding intent is retained as ENFORCEMENT state; the sugar is never emitted twice. Coexistence: grants join across sugar and explicit entries while binding floors conflict in favor of most-restrictive intent. Absent-defaults per source class: legacy driver modes imply policy; extension placements without matching rights refuse; known baselines are supplied by the owning provider; unmatched explicit targets fail typed. Staged-hook, file, socket, and image-baseline cases are covered. `[supplements]` knobs stay per-extension, guest-validated, and cannot smuggle a permission override around the central vocabulary: a closed reserved key namespace lets the framework recognize permission-shaped keys generically (no backend-specific inference over opaque strings) — matches refuse typed, and each guest's declared knob schema rejects the rest. File/kernel binding constraints get an explicit generic IR representation even where config syntax stays sugary. No explicit-deny config promise beyond what every backend can enforce-or-refuse.
- **Relocation equivalence (amendment 2026-10-14).** `revise_ro_for_confinement`, grant computation, and FULL-source/alias semantics move from framework code to the landlock-owned compiler with behavior pinned at the move: the denial matrix, alias preflight outcomes, materialization shapes, and plain-session verbatim pass-through are repinned in the relocation commit — no intermediate state where neither copy owns the behavior. DOMAIN decisions (RO→RW compilation, FULL-source/alias semantics, baseline paths/masks) relocate; genuinely generic schema/identity/provenance/phase/lifecycle gates stay in framework.
- **Namespace and deny (amendment 2026-10-14).** Guest-visible paths are the permission namespace for container and Bubblewrap-like consumers; a permissions-only host isolator explicitly describes its execution namespace (identity mapping only where it truly is the host view) — never canonicalize a future guest path as a host path by convenience. VFS-carried deny is Landlock-combination doctrine, not universal: the union cannot subtract a child denial from a FULL ancestor, so hard readonly/deny constraints are defined separately from minimum `Read` grants, and each backend enforces them or refuses unsupported rather than joining them away. A permissions-only isolator is supported by an empty placement plan or an explicit capability refusal for requested placement — not accept-then-ignore.
- [Risk] Carveout derivation reads the wrong field during migration (rights vs triple modes) → confinement silently widens or narrows. → Migration: move derivation to permissions in the same commit as the shape split; repin the full denial matrix in that commit, no intermediate state. The single-source-of-truth map makes "wrong field" a compile-time shape question, not a per-consumer audit.
- [Risk] A third extension's hooks slip past admission → unconfined or double-wrapped launch. → Admission refusal is pre-merge (no session exists yet); plus a launch-plan-time assertion that exactly ≤1 hook set reaches `compose_hook_argv` as defense in depth; plus the single-request rule so one greedy guest cannot smuggle two.
- [Risk] Old guests fail opaquely against the new host (or vice versa). → Epoch refusal names expected vs offered VERSION on both sides at the hello layer; mismatched bodies never reach shape decoding, so no silent misparse is possible in either direction.
- [Risk] Provenance multimap masks a merge bug (a name with no recorded contributor). → Missing provenance is a typed internal refusal, never a fallback identity; the old `"pair-unknown"` guess goes away entirely.
- [Trade-off] Single `prepare_many` path means pair sessions pay N-path generality — negligible (same loop, same merge); one semantics to pin outweighs a saved branch.
- [Risk] Relocation drifts behavior (neither copy owns it mid-move, or the owner subtly redefines a guarantee). → Relocation lands in one commit with the denial matrix, alias outcomes, materialization shapes, and plain-session verbatim repinned in that commit; framework keeps generic grammar/coverage/binding checks so drift fails loudly.
- [Risk] Sugar double-emits (a ro mount yields both an implied `Read` and a duplicate explicit entry) or an explicit entry contradicts sugar silently. → Single canonical IR early: decomposition runs once, explicit entries join by rule (grants join, floors most-restrictive), contradictions surface as typed conflicts, never silent overlap.
- [Risk] `[supplements]` smuggles a permission override around the central vocabulary. → Supplements stay opaque per-extension knobs, guest-validated; any permission-shaped key inside supplements refuses typed at framework validation.
- [Trade-off] Join (not refusal) for multi-claimant same-target rights means two extensions can each widen `/tmp`-style targets up to `Full` by declaration. This is intended: declarations are authoritative intent (operator doctrine), each claimant is recorded, and the lattice plus alias guards still bound the result. Refusal would break the flagship pair.

## Migration Plan

1. Shape split + version gate (contract + guests + profiles 1:1, hello-layer unit tests) with derivation moved and matrix repinned — one commit.
2. `prepare_pair` → `prepare_many`, v1 gate deleted, per-guest admission hardening (credentials/permissions/claim-scope/provenance) — one commit.
3. Hook registry phases with concrete sequence (prepare / compile / inject-supervisor / records-only finalize); revision + grant computation relocate to the landlock-owned compiler with equivalence repinned — one commit (or two: registry first, relocation second).
4. Config `[[permissions]]` + sugar decomposition with coexistence pins — one commit.
5. N-runner proof (≥3 hosted guests) + landlock+tmpdir re-proof (fast + QA live tier), reviews, land.

Rollback: revert commits in reverse; no data migration (session-scoped state only).
