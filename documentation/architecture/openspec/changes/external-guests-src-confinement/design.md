## Context

The framework half (archived `2026-09-25-framework-isolators-extensions`) delivered contracts, the stdio host, prepare/policy/seam, and fixture-only guests. `conduct` still drives the in-process `PodmanIsolator` directly; no guest binary is spawned in production and no prepare transaction carries live traffic. Fleet seats run 0.1.x with `~/src` mounted broadly RW and no confinement. Owner seat is containerized (no podman/systemd); QA tandem seat carries all live proof. Operator blocks 0.2.0 fleet deploy until real isolator + extension architectures are demonstrated with `~/src` safe.

## Goals / Non-Goals

**Goals:** Podman lifecycle over the stdio wire through a real guest binary; Landlock extension answering real `prepare` plus guest-hook delivery; `~/src` subtree confinement demonstrated with denial evidence; conduct switched to the external path behind the unchanged-seat proof.

**Non-Goals:** additional isolators; separate crates/workspace split; seat-runtime-dir provisioning (seat-socket stays fixture-only per the standing tier-2 disposition); per-profile denials; mid-session observation; fleet profile migration (0.1.x runs unchanged).

## Decisions

- **Same-crate `--bin` guests, not separate crates.** One version, one release, one `cargo install` delivering `cistella` plus guests; discovery via the install sibling directory (current-exe-relative), never PATH-searched, satisfying the pinned-discovery rule with zero new machinery. Rejected: separate crates (version skew between driver and guest, publishing chore, no benefit at this scale).
- **In-process impl stays as conformance reference.** `PodmanIsolator` keeps driving fast unit tests and the lifecycle-fidelity suite; production `conduct` uses the wire guest. The two must agree by construction (shared wire-schema types), and any divergence is a conformance failure, not a judgment call. No flag-gated production fallback exists in 0.2: a missing or crashed guest fails conduct loudly (typed discovery/timeout error) and never silently falls back to in-process execution or skips Landlock. Rejected: keeping the in-process production call as fallback (a silent confinement-skipping path is worse than a loud failure) and deleting the in-process path (loses the fast suite and the only debugger-friendly backend).
- **Confinement rule shape from the session directory.** The project subtree is already canonicalized in `conduct` (`~/src/<project>` or `~/src/CLONES/<project>/<lane>`); conduct translates it through the validated guest mount topology, and the Landlock guest grants R+X on the translated guest ancestor route with full rights on the translated guest subtree route — union semantics make the exception exact with no new profile schema and no per-seat rules to author. Rejected: profile-declared confinement rules (new schema, new audit surface, for a shape the driver already knows).
- **Denial evidence, not intent review.** The gate is attempted writes failing with `EACCES` in live conformance (spike three-way style extended to the subtree), plus the unchanged-seat proof for everything else. A design doc claiming safety is not evidence.
- **Guest binaries ship.** `package.include` must cover the new bins; the fake peer stays excluded. Install footprint grows by two small helpers alongside `cistella`.
- **Trusted install directory assumption (explicit).** Sibling-relative discovery plus opened-FD digest avoids PATH and replacement races, but same-crate shipping does not authenticate a malicious sibling planted before planning. 0.2 assumes the install directory and both binaries are operator-owned and unmodified (standard installed-software trust); both bins must ship together and a guest/version mismatch SHALL fail hello before any mutation. Separate crates are not required under this explicit assumption.
- **Removal tombstones reconcile repeatability with eviction (task 2.3, operator-approved 2026-09-26).** Successful `remove` evicts the live binding and executions on both backends and records a minimal tombstone keyed by the original handle: identical `terminate`/`remove` retries converge residue-free through idempotent backend cleanup (never resurrection; always-delegate, no synthesize-on-clean probe), divergent live attempts — including same-handle `create` — refuse typed. The base replay promise narrows to live-only (see the MODIFIED replay-scope requirement in the change's isolator-contract delta). Tombstones are process-scoped; no explicit eviction. Rejected: per-side divergence ("wire refuses, reference succeeds") and live-record retention (violates eviction).
- **Pre-exec recovery by conduct-owned re-exec (task 2.3, Advisory-concurred 2026-09-26).** On proven guest death (`guest_dead && !shutdown_uncertain`) during create/initiate, conduct retires the dead client (close/join/unlink, latches immutable), hosts a fresh `WireClient` under the still-held creation-window guard, and replays the same key/spec with a new framework handle — one bounded replacement for the whole pre-exec episode, not one per op. Second death fails stop with the second error dominant and first context retained; re-host failure converges directly by name with a residue-dominant report (never nested teardown under the held lock). Uncertain shutdown never re-execs. Death detected at `execute_launch` submission is execution-boundary, not pre-exec: the guest spawns before replying, so no-reply does not prove no execution existed, and re-launch could run the harness twice — typed teardown, never replay. Narrow exception: provably local refusal before the op reaches the guest (fd clone/bundle failure) is a local error, not a death, and retries nothing. Rejected: in-client self-heal (would reset the death latch, violating latch-never-reset).
- **PTY foreground join travels with the launch binding.** The guest spawns from its own background group (kill semantics), so a harness touching its PTY from that group stops with SIGTTIN/SIGTTOU. `StdioBinding::HeldFiles` therefore carries launch-scoped conductor identity `(pid, foreground pgid)` — the only party that observes the conductor is the guest (its parent, verified against the startup-recorded pid so subreaper adoption fails), and the only party that spawns into the group is the backend (which re-verifies both halves in pre_exec and propagates setpgid failure as typed refusal). Rejected: dropping the GUEST's spawn-time independent setpgid so it inherits the conductor foreground group directly would break group-kill and the pipe-EOF supervision (drain-to-EOF on the guest's stdout assumes the guest's process group is independent). `tcsetpgrp-steal` by the guest reroutes SIGINT away from conduct. Dropping `-t` loses the terminal. Compatibility: `Inherit` and all trait method shapes unchanged; only the `HeldFiles` variant payload grew (single construction site, guest launch arm).
- **Hook artifact is a framework-owned local digest registry, one shipped wrapper (task 3.1/3.2, Advisory ruling 2026-09-26).** The base hook payload (extension-protocol spec:48) mandates digest-pinned-blob plus sha256 plus source registry/path with isolator staging; the shipped `GuestHookRequest` shape (order/argv_prefix/probe_op) is incomplete and aligns first. Conduct resolves only admitted registry ids/paths, opens and pins the bytes, verifies the digest, copies into isolator-owned private per-session staging, re-verifies the staged bytes, and mounts RO at a known guest path before initiate; failure removes the staging and fails pre-exec. Admission is the exact `(shipped, cistella-landlock-wrap)` pair — extension input selects among table entries, never names files; opens are `O_NOFOLLOW` (terminal symlinks refuse, never follow) with size plus digest bound to the single opened FD. The hook executable binds to the staged artifact: `argv_prefix` must be exactly the singleton staged guest path (the prepare payload carries no session context, so session-blind extension args are never legitimate; the framework composes all wrapper arguments at launch). Rejected: extension mount contribution alone as executable provenance (digest-check of a mutable host path followed by a later path bind is a replacement/TOCTOU window, and contradicts the exact payload). A private verified copy mounted RO is the staging mechanism inside the digest-blob shape. An isolator-staged-path variant would need an operator-approved MODIFIED exact schema with equivalent provenance proof, not inference from the admitted-kinds sentence.
- **Interim 3.1 fail-closed gate (lane BLOCKERs 2026-09-26, removed in 3.2).** Until staging/probe/apply land, conduct refuses pre-create (typed, before unit/scratch creation) on any nonempty hook set — a requested-but-undelivered hook must never run the harness unconfined. The gate call is replaced by staging in 3.2 and must never survive alongside hook execution. Likewise the central merge sees the full occupied baseline including credential-surface mounts, and the final merged topology re-validates plus nested-RO preflights pre-create.
- **Probe by guest-context exec; apply inside the launching wrapper lineage (task 3.2, Advisory ruling 2026-09-26).** The capability probe runs after initiate as a separate `podman exec` in the real container namespace/seccomp/mount context and reports typed ABI/rights. Apply is NOT a separate exec: `landlock_restrict_self` binds the calling thread and its future descendants, so a standalone apply process would prove only its own confinement while the real harness ran unconfined. The wrapper that will exec the harness sets no-new-privs (or holds privilege), constructs and applies the rules, emits a typed applied attestation before any harness argv runs, then execs the harness in that same lineage; the guest gates `execute_launch` success on the pre-exec attestation. No new `isolator.*` ops are needed for this; any future op must gate that same paused wrapper process, never restrict in a different process.
- **Diagnostics ride a fourth framework-owned FD in the launch bundle (task 3.2, Advisory ruling 2026-09-26).** The 3-FD legacy framing stays; hook-enabled launches add a fourth FD with count/header role binding and session identity. The framework retains and drains the read end concurrently under size/deadline/redaction bounds; the guest forwards the write end into the container wrapper — via the exact `podman exec --preserve-fd={n}` list form at its natural number where the seat podman advertises it (crun runtime, preferred: robust regardless of the guest fd table), else via `--preserve-fds=1` with the write-end duped onto fd 3 pre-exec (proven contiguous `[3,3+N)` semantics: any gap fails closed; EOF on close is clean). The plural path holds by dup+N mechanics (container-visible set exactly `{0,1,2,3}` — ambient inheritable fds stay podman-side-only, proven live when the census fired on test-runner plumbing without any container-side effect); a per-launch check that the diagnostics fd itself is inheritable guards the load-bearing fact on either path. No whole-table census: it refuses on invoker plumbing (shells, agentmux pipes) without buying container-side safety. Podman floor: the guest resolves the strategy from `podman exec --help` (definition-line match) and refuses typed pre-spawn only when podman cannot run at all. Neither form is available on remote clients. Runc is admitted on the plural path only, on hand-characterized evidence (podman 4.9.3: identical N-counting, numbering, contiguity gate, EOF, arriving tables); singular exact-fd forwarding stays crun-only per podman docs (other runtimes an uncharacterized risk — refused); anything else refuses on either path. Stock Ubuntu 24.04 (podman 4.9.3, default runc) confines with distro packages and no config trickery. If the singular form ever proves unforwardable, diagnostics needs a separate operator-approved transport change — never silent stderr or pathname fallback.
- **ABI gate is authoritative in the guest-context probe with a fail-closed apply recheck (task 3.4, Advisory ruling 2026-09-26).** The probe calls `landlock_create_ruleset` with `LANDLOCK_CREATE_RULESET_VERSION` and demands the required handled-rights set including TRUNCATE (ABI 3+) plus REFER/write/create/unlink/rename rights; shortfall returns typed Unsupported pre-execute and the mask is never silently reduced. Host or extension pre-prepare checks are early hints only — they cannot certify the container context. Apply-time failure still aborts before exec and reports typed pre-execute failure via diagnostics/control attestation; no harness outcome is fabricated. The spike helper stays ABI-v1 test tooling; the shipped wrapper negotiates the full matrix.

## Risks / Trade-offs

- [Risk] External guest crash mid-lifecycle strands a unit → Mitigation: reconciliation by key already specced and conformance-pinned; pre-exec crashes recover by re-exec of the stateless guest, while death during execute/await converges to clean via typed teardown (no handle resurrection). Full cross-crash execution survival is deferred, not promised.
- [Risk] Landlock unavailable (old kernel, no no_new_privs path) → Mitigation: helper's typed `Unsupported` already proven; conduct fails pre-execute with a capability error, never silently unconfined. Confinement is fail-closed or absent-loudly, never absent-silently.
- [Risk] Extra process hop per lifecycle op → Mitigation: negligible against container-operation latency; bounded by the existing framework deadlines either way.
- [Risk] Conduct switch regresses fleet seats → Mitigation: the dogfood gate repeats (unchanged-seat proof + fleet sweep) against the external path; rollback is revert to the in-process call.

## Migration Plan

Land as additive bins plus a conduct call-site switch; fleet profiles and session state untouched. Rollback is commit revert (in-process path remains compiled and tested throughout).

## Confinement Direction (operator, 2026-09-26)

- Landlock is the primary read-only layer over read-write mounts: the 0.2 goal is declaring the `~/src` ancestor mount RO and having the framework convert directory-RO triples to RW for Podman (so submounts materialize), while the in-container policy — derived from the ORIGINAL declared modes — enforces read-only with carveouts (subtree, scratch, session mounts). File-source triples keep Podman-level RO (a file cannot root a `path_beneath` rule). No Podman RO removal beyond the mechanical conversion: defense in depth stays for 0.2, fleet profiles untouched.
- Carveouts generalize (operator, 2026-09-26): not only the session subtree, but every read-write declared directory mount grants full rights on its guest target — per-project grafts under shared read-only trees, harness state dirs, any RW submount. Profile declarations are authoritative intent; Landlock enforces, never second-guesses. Task 3.3's refusal narrows accordingly to undescribable shapes (untranslatable paths), not to declared mounts. The 3.4 denial scenario uses a sibling WITHOUT a declared RW carveout; a separate graft-admission proof pins the declared-RW exception (both live in the hooked confines test).
- RO-under-FULL retention (tier-2, 2026-09-26): a declared-RO directory at or under a FULL-granted guest route keeps its Podman binding read-only — Landlock union cannot subtract the parent FULL grant and rights propagate across bind aliases, so flipping it would leave the RO source writable through the FULL route. An RO directory holding a declared RW descendant refuses pre-create as contradictory (neither retention nor flip holds). Pinned pure (revision + preflight) with a live write-denial proof through the alias.
- Dentry-alias refusal (proven live, 2026-09-27): Landlock rules are dentry-based and mount-agnostic — a read-write graft of ancestor-tree content outside the subtree aliases RO-covered content, and the graft FULL admits writes through EVERY alias (the first hooked-launch live run admitted the denied sibling write through exactly this shape: the fixture grafted the sibling's own source). Same-source different-rights binds are contradictory declarations: the product refuses them pre-create (`graft_alias_preflight`: RW directory source strictly under the ancestor but outside the subtree). Graft content must live outside the bound tree (disjoint dentries, the Dropbox-Notes shape) or inside the subtree (already FULL); inside-tree graft targets keep the mountpoint-placeholder contract (production nested_ro requires the chain to pre-exist in the RO ancestor source). Path-based over declared topology only — adversarial bind-mount aliases sharing dentries under different paths evade it; dev+ino hardening rides task 3.3.
- Extension mounts never compose into carveouts (tier-2, 2026-09-26): merged mounts are extension-provided by construction, and no Mounts policy admission exists — extension RW triples refuse at prepare, so a compromised extension cannot grant itself FULL. Extension RO contributions still merge (bus-socket vectors) but compose only into readability, never writes. Lifting this refusal requires explicit policy admission, not a capability advertisement.
- Companion scope (operator, 2026-09-26): the confinement guarantee covers the wrapped harness lineage only. Companion exec (`cistella enter`, plain `podman exec`) runs outside Landlock by design — the operator is trusted and holds host-equivalent access, so restricting their own shell overcomplicates against no defended principal. The hooked unit marker stays as confinement state (and as the signal a future wrapper-sidecar path keys on).
- No new lifecycle phases: `prepare` is the pre-initialization engagement (extension answers, framework revises mounts, merge validates), and probe/apply/launch is the post-initialization engagement (guest-context probe, wrapper lineage apply with attestation, composed launch). The hook points enumerated at spec start suffice.
- System baseline (operator-decided, mechanical composition): read-execute on the container rootfs (loader/interpreter/libc under default-deny), full rights on `/dev` (container-private devtmpfs; null/shm/ptmx function), full on the subtree and outside-ancestor read-write session mounts, read-execute on outside read-only mounts. `/tmp` and container `$HOME` writes stay denied (outlet: `/tmp/scratch`); the host-`/tmp`-subdir bind is deploy-side follow-up. Unix-socket connect semantics under confinement are an explicit dogfood risk.
- Status-separation scoping: EOF on the exec-sealed diagnostics fd is necessary but not sufficient for exec transition (a SIGKILL between seal and execve looks identical). The design closes it with supervision, not new machinery elsewhere: the restricted wrapper forks after attesting; the child execs (errno on a CLOEXEC err-pipe on failure) while the parent classifies the boundary — errno bytes mean exec failed, EOF with the child alive means transitioned (a live pre-exec child still holds the write end, so EOF could not have arrived), EOF with the child dead means wrapper-death — and reports it typed (`transitioned:true/false`) before supervising the harness to its disposition (exit codes relay verbatim, signals re-raise). The host gate requires attestation AND transitioned AND EOF; every other shape fails typed. Clean harness exits prove exec (only the harness produces them post-transition); exec failures report with cause. Race-window signals (indistinguishable pre-exec wrapper death vs early harness signal) classify as `transition ambiguous`, never as wrapper failure and never as a harness outcome — exact signal fidelity holds post-transition only (operator-accepted 2026-09-26: Ctrl-C and crash reporting during harness runs are unaffected; only signals landing between fork and transition-emit take the ambiguous path). A QA-gated fault seam (`CISTELLA_QA_WRAPPER_FAULT=kill-after-attest`) pins the window deterministically.
